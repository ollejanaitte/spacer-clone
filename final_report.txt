調査結果（S1 中のバリデーション不整合の発見と解決）:
- 症状: サンプル入力（対傾構 横桁1本ごと = swayBracingInterval=1）で検証が失敗した。
  - validateBridgeStructureInputDraft → complete=false
  - 診断: 「対傾構間隔（横桁N本ごと）は 1 より大きい値を入力してください。」
- 原因: BRIDGE_STRUCTURE_INPUT_FIELDS の swayBracingInterval が min: 1 で定義されており、
  validation.ts の validatePositiveNumber は value <= min をエラーとするため「1 より大きい」=2 以上を要求していた。
- 矛盾: フィールド定義（横桁N本ごと）と S0 サンプル仕様（対傾構 1 本ごと）は N=1 を許容すべきだが、
  既存バリデーションは 1 を拒否していた。
- 解決: types.ts の swayBracingInterval を min: 1 → min: 0 に変更（1 以上を許容）。
  - min: 0 により value=0 は引き続き拒否（0 より大きい、=整数で1以上）、value=1 を許可。
  - 既存テスト（0 拒否 / 1.5 非整数拒否 / 2 許可）はすべて維持。
  - generateBsdd.ts / quantities.ts の index % swayBracingInterval ロジックは 1 で全横桁に生成され問題なし。
- 影響: 追加・既存含め全 257 テストが通過。
