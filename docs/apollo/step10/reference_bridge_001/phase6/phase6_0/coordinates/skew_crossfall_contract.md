# Skew / Crossfall Contract

> **Authority:** Reference Bridge 001 (RB-S10-001) — STEP 10 Phase 6-0 PR-2
> **Frozen** by this PR.

## 1. Skew

- `skew` = angle between a transverse line (e.g. support line / pier line) and the
  alignment normal (transverse axis).
- Canonical unit: **radians**. Display deg preserved; source deg recorded on values
  (no silent conversion).
- Positive skew convention: rotates the transverse axis about the vertical axis in
  the +Z (CCW looking down-station) direction, per existing `skewRad` (+Z CCW).
- `skew = 0` => line perpendicular to the alignment.

## 2. Skew authority

- Support line skew is generated by the Geometry Engine (support geometry) and
  carried in GeometrySnapshot support entities.
- Consumers receive skew from the snapshot; they never recompute it.
- The legacy split (rad in frontend/project.schema vs deg in substructure
  schemas/prototype) is resolved: canonical rad; deg only at UI/format boundary with
  recorded source unit.

## 3. Crossfall

- `crossfall` = transverse slope, percent.
- Sign convention: **right-down-positive** (matches LINER crossfall + existing
  `signConventions.crossfall`).
- Crossfall authority: LINER (`crossfallResolution`, `crossSectionZMerge`).

## 4. Prohibited

- Consumer-side skew rotation (viewer/drawing/structural must not re-apply skew).
- Consumer-side crossfall re-derivation.
- deg/rad ambiguity (always record source unit when not canonical).
