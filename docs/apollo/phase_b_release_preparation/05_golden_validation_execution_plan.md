## 1. Golden の定義

Golden とは、**独立に誘導・実行された期待値と、対象 solver の出力を機械的に比較**し、一致を判定する基準ケースである。

| 種別 | 期待値の独立性 | 対象（07_validation_cases.csv 対応） |
|------|----------------|--------------------------------------|
| ANALYTICAL_GOLDEN | 閉形式解析解を**独立に手誘導**（対象 solver の計算経路に依存しない） | GOLD-001..005, GOLD-010, GOLD-015 / VC-AN-00x |
| PARITY_GOLDEN（REFERENCE_SOFTWARE） | 固定版外部解析器（SPACER）の実実行 3 回出力 | GOLD-006..009 / VC-PAR-00x |
| APPROVED_REGRESSION_GOLDEN | 契約由来の oracle（STALE・拒否・エクスポート） | GOLD-011..014, GOLD-016 |
| DESIGN_VERIFICATION_GOLDEN | 基準採択ソースからの独立誘導（照査比・判定） | GOLD-015 / VC-STD-001/002 |

**重要な規則（fail-closed）:**
- 対象 solver（リポジトリ内 solver）が生成した値を期待値にしない。
- DeepSeek（モデル）による再計算を独立証拠にしない。独立誘導は人間の手計算・独立ツール・基準採択ソースに基づく。
- テスト PASS だけで数値実装を許可しない。許可は Golden 承認 + 08 ゲート昇格（DEC-ID）を要する。

---

## 2. 独立性条件

| 条件 | 要件 |
|------|------|
| 誘導独立性 | 期待値の導出が対象 solver のコード・実行結果に依存しないこと |
| 実行者分離 | 期待値作成者と solver 実装者・承認者が同一人物であっても、独立手順・独立ツール・独立証跡を要する |
| ツール分離 | 手計算・電卓・独立解析ツール・表計算ソフト等、対象 solver と異なる経路で誘導 |
| 承認分離 | 承認者は誘導と実行の記録を独立に確認し、DEC-ID で承認 |
| 証跡保存 | 誘導メモ・計算過程・単位換算・比較スクリプトを証跡として保存 |

---

## 3. 同一モデル生成値を独立証拠にしない規則（明示）

以下を**禁止**する:

1. `backend/engine` の solver をそのまま使って期待値を生成し、それを Golden と呼ぶこと
2. 同一モデルを solver で 2 回実行し、結果が一致したことを独立検証とみなすこと
3. DeepSeek が solver と同じ計算をコードで再現し、一致を「独立証拠」とすること
4. 既存テスト（`test_engine_verification_cases.py` 等）の PASS を Golden 承認の代替とすること
5. 道示・正誤表・JIS 等の**未確認一次資料**の数値を期待値に採用すること

## 5. 最小候補 Golden 一式（GOLD-MG-001..007）

Phase B で最初に独立検証すべき**基礎量**を、solver 非依存の閉形式で定義する。これらは 07_validation_cases.csv の VC-AN-00x / GOLD-001..005 と整合するが、**主桁設計文脈の量**として再構成した計画上の候補である。

| ID | 対象 | 入力 fixture | 期待中間値 | 期待最終値 | 単位 |
|----|------|--------------|------------|------------|------|
| GOLD-MG-001 | 単純支持主桁・自重（等分布） | 等分布荷重モデル（断面・材料・支間固定） | 支点反力 = wL/2 | 中央たわみ = 5wL⁴/(384EI)、最大曲げ = wL²/8 | kN / m / kN·m |
| GOLD-MG-002 | 単純支持主桁・集中荷重 | 中央集中荷重モデル | 支点反力 = P/2 | 中央たわみ = PL³/(48EI)、最大曲げ = PL/4 | kN / m / kN·m |
| GOLD-MG-003 | 断面諸量の独立手計算 | 主桁断面（鋼鈑桁 1 種） | A / Iy / Iz の部材分断・合成規則 | 断面諸量 A, Iy, Iz（J はねじり定数） | m² / m⁴ |
| GOLD-MG-004 | 支点反力 | 各荷重ケース | 静的平衡 ΣFy = ΣR | 各支点反力 | kN |
| GOLD-MG-005 | 最大曲げモーメント | 各荷重ケース | 断面力図の形状 | Mmax | kN·m |
| GOLD-MG-006 | 最大せん断力 | 各荷重ケース | 断面力図の形状 | Vmax | kN |
| GOLD-MG-007 | 最大たわみ | 各荷重ケース | 支間比・たわみ形状 | δmax | m |

### 5.1 入力 fixture 仕様（GOLD-MG-001/002 の例）

- 支間: 設計対象主桁の代表支間（例: 30.0 m）。**数値は採択済み値のみ使用**（未採択の場合は `CANDIDATE` として固定）。
- 断面: 鋼鈑桁断面（フランジ・ウェブ・補剛材を明示）→ A / Iy / Iz を独立手計算で確定。
- 材料: 弾性係数・せん断弾性係数・単位体積重量（PA-OQ-008 / VR-R7-I-003 の確認完了後にのみ採択）。
- 荷重: 自重（等分布）は断面積 × 単位体積重量 × 重力加速度。活荷重は基準採択後に追加。
- 単位系: SI（kN・m）。モデル・期待値・solver 出力の単位束縛は AN-BLK-003 の BLOCKED を解除しない限りラベルとして扱う。

> **注:** 上記の数値は**計画上のプレースホルダ**である。道示 R7 目視確認（UA-P2-01）・材料値確認（UA-P2-04）・JIS 特定（UA-P2-02）が完了するまで採択しない。

## 6. 期待値の誘導方法

| 量 | 誘導方法（独立） | 独立性の担保 |
|----|------------------|--------------|
| 断面諸量 | 部材要素の図式分解 + 手計算（または独立断面計算ツール） | 対象 solver の断面計算に依存しない |
| 反力 | 静的平衡 ΣF = 0 の手計算 | 平衡式のみ |
| 曲げモーメント・せん断力 | 断面力関数の手積分・独立公式 | 梁理論の閉形式 |
| たわみ | 閉形式たわみ式（等分布・集中荷重）または独立解析 | 重ね合わせ・境界条件の手検証 |

**禁止:** 対象 solver を実行して出力を期待値に転用する行為。

## 7. 許容誤差・比較規則（DS-07 既定を踏襲）

既存 `tolerance_freeze_register.csv`（EA-02）の既定を基準とし、GOLD-MG も同様の規則を事前に固定する。

| 項目 | 値 | 根拠 |
|------|-----|------|
| 比較規則 | `abs(a − e) <= max(A, R·|e|)` | DS-07 既定 |
| 絶対誤差 A（閉形式モデル） | 1E-15（定義モデルの理想化誤差なし）〜 1E-9（実モデル） | 固定ユニット誤算予算 |
| 相対誤差 R | 1E-12（閉形式）〜 1E-6（実モデル） | DS-07 既定規則 |
| ゼロ閾値 | 1E-20（閉形式）〜 1E-14 | 表示丸めとの分離 |
| 丸め規則 | 比較前に固定（表示丸めから符号・値を推測しない） | DS-07 |
| 内部精度 | 64bit float を超える桁を要求しない | 数値基盤の観察 |

誤差固定は**比較実施前に決定し、freeze_register へ記録**する。基準・単位・モデルを変えながら誤差を後付けしない。

## 8. チェックサム・版管理

- 入力 fixture は `sha256_content_checksum`（`if3_checksum.py` と同規格: canonical JSON、sort_keys、非有限値拒否）で固定する。
- 期待値成果物・実行出力も同規格でチェックサムを記録する。
- solver / ツールの版は SemVer で記録（solverName: `scipy_sparse` / `newmark_beta`、solverVersion: `0.3.x` が IF3 サポート対象）。
- 実行環境（OS・Python・numpy/scipy 版・BLAS）を記録する。

## 10. 出力ファイル・再現手順

実行ごとに以下の出力を保存する:

| 成果物 | 内容 |
|--------|------|
| input_bundle / fixture_checksum_manifest | 固定済み入力とチェックサム |
| derivation artifact | 独立誘導メモ・計算過程・単位換算 |
| solver output bundle | 実行結果 JSON（envelope）+ 実行時刻・環境 |
| comparison report | 比較スクリプト・差分テーブル・判定 |
| approval record | 承認者・承認日・DEC-ID |

再現手順: チェックサム固定の入力 + 固定版環境 + 固定版 solver を実行し、出力を再比較して同一判定を得ること。**再現できなければ承認しない。**

---

## 11. 差分判定・失敗時処理

- 判定: 全対象量が許容誤差内で一致 → `MATCH`。1 つでも超過 → `MISMATCH`。
- `MISMATCH` 時の処理:
  1. 実行失敗・入力不整合・環境差異（solver 版・BLAS）をまず確認
  2. 誘導ミス（期待値側）か solver 出力（実行側）かを分離
  3. 修正後、チェックサムを再固定して再実行
  4. 修正が solver 実装変更を要する場合は application code 変更（Phase B）として、本 Phase A+ では停止し 07 に記録
- 未解消の `MISMATCH` がある限り、該当 Golden は `NOT_APPROVED`、対応する 08 セルは `NOT_AUTHORIZED` を維持する（fail-closed）。
