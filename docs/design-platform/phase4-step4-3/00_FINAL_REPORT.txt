CANONICAL_POLICY:
  - A CANONICAL = envelope(schemaId/documentId/documentKind/revisionId/contentChecksum/provenance)
    + body; canonicalJsonForChecksum (sorted keys, NaN/Infinity reject) + sha256 contentChecksum.
  - Saved via AtomicJsonStore (temp->fsync->replace->dir fsync). Readback checksum-verify; fail-closed.
  - manifest = ToC (no embedded payload). BridgeProject docs VERBATIM canonical (verbatim reuse of cbdmDocument serialize/parse + validateBridgeProject).

RESULT_EVIDENCE_POLICY:
  - B RESULT = displacements/reactions/member-force/quantity/design-result/audit/reports/AnalysisResult/Deliverable.
  - Stored as canonical docs (persisted-result kind) + resources/. Regenerable but kept (evidence).
  - Included in backup/package by default (large via exclude option).

CACHE_POLICY:
  - C CACHE = viewer scene cache/thumbnail/preview/temporary geometry. .system/cache/ only.
  - Excluded from package/backup; regenerable; safe to delete. localStorage UI settings = app config (not project data).

STABLE_ID_POLICY:
  - UUID (uuidStringSchema / generateUuid; deriveStableUuid for deterministic bridge refs).
  - documentId = UUID (rename-safe). entityId (in-doc) = StableEntityId(namespace+UUID+entityKind+aliases).
  - human-readable (projectNumber/name/road名称) = display only, NOT primary key.
  - copy -> deep re-id; import -> collision detect (AtomicJsonStore create_only) + remap.

REFERENCE_POLICY:
  - DocumentReference (kind:id:revision+checksum+uri). identity = "kind:uuid:revision".
  - revision in ref = positive int (no floating latest) -> stale detection.
  - checksum in ref -> dangling/tamper/mismatched-revision detect -> fail-closed.
  - uri = project-root relative (portability; path != identity).
  - EngineeringProject/BridgeProject already use this; BusinessProject extends it.

PATH_POLICY:
  - path = location (human-readable <documentId>.<kind>.json), identity = documentId+revision+checksum.
  - resources = content-addressed resources/<sha256>.<ext>.
  - rename/move -> update uri in manifest only; refs by ID survive.

FORMAL_SAVE_POLICY:
  - dirty -> schema validate -> reference validate (dangling/checksum/revision) -> dependency validate
    (incoming refs; fail-closed) -> WritePlan -> each child atomic publish (AtomicJsonStore) ->
    manifest last commit (revisionId+1, contentChecksum recompute) -> readback checksum verify.
  - manifest = last commit; crash leaves old consistent manifest + orphan children (recovered by journal).

MULTI_FILE_TRANSACTION_POLICY:
  - RECOMMENDED: Option A (children-first atomic + manifest-last commit) + lightweight recovery journal.
    - Why: portable (each file atomic via existing AtomicJsonStore), manifest-last = logical atomicity,
      crash yields only orphan children (recoverable), no cross-volume/Windows-dir-swap fragility.
    - REJECTED: B folder-swap (Windows empty-dir-only os.replace; cross-volume fail), D manifest-first (dangling refs).
    - Option C (full journal) is V2; Prototype uses A + minimal journal.

AUTOSAVE_POLICY:
  - Separate from formal Save. Staging in .system/autosave/ (manifest + dirty children). formal
    manifest.revisionId NOT bumped by autosave (autosave.meta.json has own autosaveRevision).
  - 5s idle debounce; 3-generation keep; dirty via contentChecksum diff vs formal manifest.
  - Autosave target: manifest + dirty child docs (NOT immutable resources/cache).

RECOVERY_POLICY:
  - .system/recovery/transaction.json intent journal (written before mutations, commit marker after).
  - Boot: commit marker check -> crash detected -> candidate比較 (formal vs autosave vs journal); newest valid selected.
  - Corrupted autosave -> checksum verify fail -> discard + warn (never overwrite formal save).
  - Recovery 후 user [Save] -> promote to formal (manifest revision bump).

HISTORY_POLICY:
  - .system/history/<revision>.json append-only log: {revisionId, timestamp, changedEntityRefs(kinds),
    manifestChecksum, backupPoint, migrationRecordRef, actor, reason}.
  - manifest stays latest-only (no full-object history). Catalog scan can rebuild folder.

BACKUP_POLICY:
  - Primary: Project Folder copy (snapshot) - simplest, recommended Prototype.
  - Portable: Package export (P14) incl history(option), excl .system/autosave,recovery,cache.
  - Snapshot/incremental: V2. .system/cache excluded; resources shared (dedup by sha).

RESOURCE_BINARY_POLICY:
  - resources/<sha256>.<ext> immutable content-addressed. ImmutableResourceReference(uri+checksum+mediaType).
  - Terrain/imagery/PDF/STL/CSV/DXF/SVG/PNG all here (no JSON embed). Dataset descriptors -> resources.
  - Missing -> warn + fail-closed on that datum only (project opens). External absolute/uri -> package inline.
  - Same content -> same path (dedup). Edit -> new binary -> new sha -> new path (immutable).

PACKAGE_POLICY:
  - ZIP (.business-project / .dpz). package-manifest.json (entries+sha256+classification, excluded list, externalResourceRefs, businessProjectId, baseRevisionId).
  - Include CANONICAL+RESULT (+history optional); exclude .system/autosave,recovery,cache.
  - Import: verify all entry checksums; reject path-traversal/symlink/zip-slip; ID collision -> remap table + ref rewrite; external uri -> inline or warn; dry-run+rollback (non-destructive).

IMPORT_EXPORT_POLICY:
  - Import = open folder OR unpack package; validate (schema+reference+checksum).
  - Export: ad-hoc Download (unmanaged) vs project-internal Deliverable (promote to deliverables/).
  - Package = portable single-file transfer (Case 8). Folder = native working form (Case 7).
