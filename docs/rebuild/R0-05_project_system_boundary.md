================================================================================
R0-05  Project System 責任境界
================================================================================
Project System を新システムの最上位として定義し、その責任範囲と
設計機能との境界を確定する。

--------------------------------------------------------------------------------
1. Project System の定義
--------------------------------------------------------------------------------
業務（Project）を単位として、
作成・編集・保存・読込・再開・成果品を統合管理する基盤。
新システムのすべての設計機能は Project System に接続される。

--------------------------------------------------------------------------------
2. 主要コンポーネント
--------------------------------------------------------------------------------
業務一覧（Business List）
  - 既存 Project の一覧・検索・作成・開く・削除
Project Manager
  - 単一 Project のライフサイクル管理（作成/開く/編集/保存/閉じる/未保存警告）
  - dirty 管理・更新時刻・バージョン
Project Data Core
  - Project Schema の適用・検証・マイグレーション
  - 正本データの保持（多重管理の排除）
  - 各設計機能とのデータ契約
  - Save / Load / Restart 復元の実装

--------------------------------------------------------------------------------
3. Project の構成（データ単位の目安）
--------------------------------------------------------------------------------
Project
├─ metadata（id・名称・件番・作成日・更新日・段階）
├─ coordinateSystem / units（一元定義）
├─ road（道路線形・縦断・横断）
├─ terrain（地形・現況）
├─ bridge（橋梁配置）
├─ substructure（下部工）
├─ superstructure（上部工）
├─ fem（FEM / 構造解析）
├─ cim（CIM / 統合3D）
└─ deliverables（成果品）

各セクションは Project Data Core が定めるスキーマに従う。

--------------------------------------------------------------------------------
4. 設計機能との境界
--------------------------------------------------------------------------------
- 各設計機能（道路〜成果品）は:
  - Project Data Core から入力データを読む
  - 計算・設計する
  - 結果を Project Data Core へ書き戻す
  - 保存は自前で行わない（Project に一元化）
- 機能間の直接データ交換は禁止。
- 機能が生成する 3D / 図面 / 帳票は「成果品」として Project に紐づく。

--------------------------------------------------------------------------------
5. 禁止事項（Phase R0 監査の教訓を反映）
--------------------------------------------------------------------------------
- 各ツール個別の保存・読込を作らない。
- React ローカル state を正本にしない（Project Data Core を正本とする）。
- 座標系を機能ごとに暗黙定義しない。
- 派生コピー連鎖（LINER→FEM→3D を別々にコピー）を作らない。
- 未保存のまま別機能へ移る際の警告を必ず設ける。

--------------------------------------------------------------------------------
6. Phase R1 での実装対象（確定）
--------------------------------------------------------------------------------
Phase R1 の対象は「新統合システム基盤・業務一覧・Project管理」。
具体的には:
- 新アプリ Shell（起動できる最小基盤）
- 業務一覧（Business List）
- Project Manager / Project Data Core の最小実装
- Project Schema と Save / Load / Restart の基本実装

道路・橋梁・FEM 等の設計機能の本実装は R2 以降。
