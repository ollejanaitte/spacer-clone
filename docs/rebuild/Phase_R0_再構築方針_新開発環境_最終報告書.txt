6. Project System 方針
================================================================================
- 業務（Project）を最上位とし、全設計機能は Project に接続する。
- Project Data Core が正本・スキーマ・検証・保存を一元管理。
- 機能間の直接データコピー・各機能個別の保存を禁止。
- 詳細: docs/rebuild/R0-05_project_system_boundary.md

================================================================================
7. Save / Load 方針
================================================================================
- Project 単位で保存・読込・再起動復元を正規経路とする。
- 目標フロー: 業務一覧→開く→設計→保存→終了→再起動→再読込（同一 Project を再現）。
- Project Schema・バージョン管理・マイグレーションを標準装備。
- 旧システムの欠陥（ダウンロードのみ・復元なし・autosave 凍結）を是正。
- 詳細: docs/rebuild/R0-06_save_load_policy.md

================================================================================
8. Git 運用方針
================================================================================
- origin/main = 旧システム安定版（保全）
- rebuild/integrated-system = 新システム長期統合 branch
- feature/* = 小さい実装単位（→ rebuild へ PR merge）
- 未完成の新システムは Acceptance Gate（E2E/Save-Load/Reference Business 001/
  regression/数値検証）通過まで main へ統合しない。
- 詳細: docs/rebuild/R0-07_git_workflow.md

================================================================================
9. KEEP / PORT / REWRITE / RETIRE 方針
================================================================================
- KEEP: そのまま利用可 / PORT: 選別移植 / REWRITE: 作り直し / RETIRE: 廃止
- 「旧画面を移植する」ではなく「旧システムのどの能力を新 Project System へ
  移植するか」で判断する。
- 予察: 解析エンジン・LINER 計算・IF3 = PORT/KEEP、
        UI・保存・BusinessProject・3D = REWRITE、
        rule_engine（DEAD）・教育ダミー = RETIRE 判断。
- 詳細: docs/rebuild/R0-08_asset_classification.md
