================================================================================
R0-08  旧資産分類ルール（KEEP / PORT / REWRITE / RETIRE）
================================================================================
旧システム資産を新 Project System へどう扱うかの分類ルールと判断基準を確定する。
Phase R0 では詳細な移植判断は行わず、ルールの確定のみ。

--------------------------------------------------------------------------------
1. 分類
--------------------------------------------------------------------------------
KEEP
= そのまま利用可能（同一コードで流用）

PORT
= 計算ロジック・API・utility 等を選別移植（新契約に適合させて移す）

REWRITE
= 新システム向けに作り直し

RETIRE
= 新システムでは廃止

--------------------------------------------------------------------------------
2. 判断基準
--------------------------------------------------------------------------------
| 分類 | 条件の目安 |
| --- | --- |
| KEEP | 純粋な計算・検証・契約で、新システムにそのまま適合し、テストも健全 |
| PORT | 価値ある能力だが、新 UI / 新 state / 新保存に合わせた改変が必要 |
| REWRITE | 旧実装が旧状態管理・旧保存に密結合で、そのままでは新基盤に載らない |
| RETIRE | 使われていない・プレースホルダ・教育ダミー・重複実装 |

--------------------------------------------------------------------------------
3. 判断の進め方
--------------------------------------------------------------------------------
- 分類は機能単位・ファイル単位で行う。
- 判断の根拠（コード・テスト・使用状況）を記録する。
- 判断が揺れる場合は暫定分類 + レビューで確定する。
- Phase R1 以降、機能ごとに「旧資産のどこをどう移植するか」を決める。

--------------------------------------------------------------------------------
4. 主要な判断例（Phase 0 / STEP 1 監査の所見を踏まえた予察）
--------------------------------------------------------------------------------
| 旧資産 | 予察 | 理由 |
| --- | --- | --- |
| backend 解析エンジン（solver/element/assembly/eigen/RS/TH/influence/moving_load） | PORT/KEEP | 実計算・pytest 充実。新契約に合わせて API 化 |
| LINER 線形計算（ldist/haunch/hoso/縦断/横断） | PORT | 計算ロジックは価値大。新 Project 契約へ接続 |
| IF3 正規化・永続化・stale 検出 | KEEP/PORT | 品質高い。新 Project に合わせて配置 |
| atomic_json（原子保存） | KEEP | 保存層の基礎として利用可 |
| メインFEM の UI・state（App.tsx 等） | REWRITE | 保存分散・多重 state のため作り直し |
| Save（ダウンロードのみ） | REWRITE | Project 一元保存に再設計 |
| BusinessProject（localStorage マニフェスト） | REWRITE | 実データ保存・正本管理へ再設計 |
| 下部工（15チェック MOCK） | PORT（計算部） / REWRITE（UI） | 計算設計は将来実装 |
| Apollo（入力のみ・解析未実装） | PORT（入力モデル） / REWRITE（解析） | 解析は未実装 |
| 3D（FEM骨組み/仮断面/サンプル専用） | REWRITE | 実設計ジオメトリ駆動へ再設計 |
| rule_engine（DEAD） | RETIRE or 再配線判断 | 現状未使用 |
| 教育フロー（学習編/入門編 placeholder） | RETIRE or 再設計判断 | 未実装 |

※ 上記は予察。正式な分類は R1 以降に機能単位で実施・記録する。

--------------------------------------------------------------------------------
5. 禁止事項
--------------------------------------------------------------------------------
- 「旧画面を移植する」という発想で丸ごとコピーしない。
- 「旧コードを動かすために新システムを曲げる」設計をしない。
- 分類根拠なしの KEEP を認めない（使用・テスト状況を確認する）。
