================================================================================
R0-04  新統合システム 基本アーキテクチャ
================================================================================
新システムの最上位構成と、将来機能の接続境界を確定する。
Phase R0 では設計機能の中身を実装しない。責任境界の定義のみ。

--------------------------------------------------------------------------------
1. 最上位構成（Project System 中心）
--------------------------------------------------------------------------------
Project System
├─ 業務一覧
├─ Project Manager
├─ Project Data Core
├─ 道路
├─ 地形・現況
├─ 橋梁配置
├─ 上部工
├─ 下部工
├─ FEM / 構造解析
├─ CIM / 統合3D
└─ 成果品

--------------------------------------------------------------------------------
2. レイヤ構成（概略）
--------------------------------------------------------------------------------
+--------------------------------------------------------------+
| UI Layer（業務一覧・Project Manager・各設計機能の画面）        |
+--------------------------------------------------------------+
| Project System Layer（Projectのライフサイクル・保存・読込）     |
+--------------------------------------------------------------+
| Project Data Core（Project Schema・正本・バージョン・検証）     |
+--------------------------------------------------------------+
| Domain Modules（道路/地形/橋梁/上部工/下部工/FEM/CIM/成果品）    |
+--------------------------------------------------------------+
| Backend / Engine / Persistence（計算・DB・ファイル）           |
+--------------------------------------------------------------+

- UI は Project System を通してのみ Project にアクセスする。
- 各設計機能は Project Data Core に定義された契約で Project へ出入力する。
- 機能間の直接データコピーは禁止し、Project Data Core 経由で共有する。

--------------------------------------------------------------------------------
3. Project System の責務
--------------------------------------------------------------------------------
- Project の作成・一覧・開く・閉じる・削除
- 保存 / 読込 / 再起動後復元
- dirty 管理・未保存警告
- Project Schema の適用・検証・マイグレーション
- 各設計機能（道路〜成果品）の登録・起動・結果受領
- Source of Truth の一元管理（多重管理の排除）

--------------------------------------------------------------------------------
4. 各設計機能の接続境界（Phase R0 では中身を実装しない）
--------------------------------------------------------------------------------
| 機能 | 境界（Project Data Core との出入力） |
| --- | --- |
| 道路 | 道路線形・測点・縦断・横断データ（スキーマ定義） |
| 地形・現況 | 地形モデル・現況データ |
| 橋梁配置 | 橋梁線形・支間・配置 |
| 下部工 | 橋台・橋脚・基礎・杭の配置と設計 |
| 上部工 | 主桁・床版・支承等の配置と設計 |
| FEM / 構造解析 | 解析モデル生成・解析実行・結果格納 |
| CIM / 統合3D | 設計データから 3D / CIM 生成 |
| 成果品 | 帳票・図面・計算書・出力 |

各機能は「Project の一部として保存されるデータ」と「生成される成果物」を分離し、
正本は Project Data Core に置く。

--------------------------------------------------------------------------------
5. 技術スタック方針
--------------------------------------------------------------------------------
- 既存の評価済み技術（React/Vite/Electron/TypeScript/FastAPI/scipy）は
  再評価の上で利用可。ただし旧実装の丸ごと流用はしない。
- Save / Load は各ツール個別の機能にしない（Project に一元化）。
- 座標系・単位は Project 全体で一元定義する。
- Schema / 検証 / マイグレーションを Project Data Core の責務とする。

--------------------------------------------------------------------------------
6. 設計原則（Phase 0 / STEP 1 監査の教訓）
--------------------------------------------------------------------------------
- 保存と復元を最優先の正規経路とする（再起動で同じ Project を再読込可能に）。
- Source of Truth を 1 つにする（多重管理・派生コピー連鎖を排除）。
- UI と計算ロジックと persistence を分離する。
- 座標系・結果・リンク（LINER→FEM 等）の同期を一元管理する。
- DEAD / MOCK / PLACEHOLDER を新システムへ持ち込まない。
