================================================================================
R0-03  新旧システム分離方針
================================================================================
新旧システムの役割・責任分離を明文化する。

--------------------------------------------------------------------------------
1. 旧システム（main）
--------------------------------------------------------------------------------
- 役割:
  - 現行安定版
  - 移植候補の調査元
  - 動作比較元
  - 数値比較元
- 位置: /home/masaharu/Projects/spacer-clone（branch: main）
- 方針:
  - 既存アプリ機能を理由なく変更しない。
  - 新システムの未完成コードを旧 main へ逐次混在させない。
  - 旧 UI / 旧 state / 旧保存方式をそのまま「正解」とみなさない。
    （Phase 0 / STEP 1 監査で、保存・Source of Truth・3D に重大な課題があることを確認済み）

--------------------------------------------------------------------------------
2. 新システム（rebuild/integrated-system）
--------------------------------------------------------------------------------
- 役割:
  - 新統合道路・橋梁設計システム（Project System 中心）
  - 新しい UI / Project Data Core / Save / Load
  - 各設計機能を後から接続する統合基盤
- 位置: /home/masaharu/Projects/spacer-clone-next（branch: rebuild/integrated-system）
- 方針:
  - ゼロベースで設計する。
  - 旧画面・state管理・保存処理を丸ごとコピーする設計は禁止。
  - 旧システムの「能力」だけを選別移植する（KEEP / PORT / REWRITE / RETIRE）。

--------------------------------------------------------------------------------
3. 責任分離の原則
--------------------------------------------------------------------------------
- 旧 main は「基準・移植元・比較対象」であり、改変しない。
- 新 rebuild は「新システムの開発場所」であり、旧コードを前提にしない。
- 二つの worktree は git 上独立しており、同時に運用できる。
- 新システムのコードが旧 main へ入るのは、Acceptance Gate 通過後の正式統合のみ。

--------------------------------------------------------------------------------
4. 移植の考え方
--------------------------------------------------------------------------------
「旧画面を移植する」ではなく
「旧システムのどの能力を新 Project System へ移植するか」で判断する。

例:
- backend 解析エンジン（実計算・テスト充実）→ PORT / KEEP 候補
- 保存方式（ダウンロードのみ・復元なし）  → REWRITE
- rule_engine（DEAD CODE）                 → RETIRE or 再配線判断
- 教育フロー（プレースホルダ）             → RETIRE or 再設計判断

詳細は R0-08 を参照。

--------------------------------------------------------------------------------
5. 禁止事項（再掲）
--------------------------------------------------------------------------------
- 旧 main の大規模改修
- 旧システムの全コードコピー
- 未完成 rebuild の main 統合
- dirty 作業の破棄 / 既存 worktree 削除 / 既存 branch の強制変更 / force push
