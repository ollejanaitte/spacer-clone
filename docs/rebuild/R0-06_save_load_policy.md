================================================================================
R0-06  Project / Save / Load 基本方針
================================================================================
新システムの保存・読込・再起動復元の基本方針。

--------------------------------------------------------------------------------
1. 中核原則
--------------------------------------------------------------------------------
Project / Save / Load / Restart / Project Schema / Project Data Core を
新システムの中核とする。

Save / Load は各設計ツール個別の機能にしてはならない。
全ての設計データは単一 Project に属し、Project 単位で保存・読込・復元する。

--------------------------------------------------------------------------------
2. 実現するユーザーフロー（目標）
--------------------------------------------------------------------------------
業務一覧
→ Project を開く
→ 道路
→ 地形
→ 橋梁
→ 下部工
→ 上部工
→ FEM
→ 3D
→ 保存
→ Electron 終了
→ 再起動
→ 同じ Project を再読込

この流れを成立させる前提で設計する。

--------------------------------------------------------------------------------
3. Save / Load の設計方針
--------------------------------------------------------------------------------
- 保存対象: Project 全体（metadata + 全設計セクション + 成果品参照）。
- 保存形式: スキーマ検証済みの JSON ドキュメント（Project Schema 準拠）。
- 保存先: 正規 Project リポジトリ（バックエンド管理 or ファイル管理は R1 で決定）。
- 読込: スキーマ検証 → マイグレーション → Project Data Core へ構築。
- 再起動復元: 起動時に「前回開いていた Project」または業務一覧から再開可能にする。
- autosave / recovery: クラッシュ時の復旧手段を標準装備する（旧システムは凍結）。

--------------------------------------------------------------------------------
4. 旧システムからの改善点（Phase 0 / STEP 1 監査の教訓）
--------------------------------------------------------------------------------
旧: メインFEMはダウンロードのみ・再起動で復元されない・autosave 凍結・
    backend 保存 API 未使用・BusinessProject は localStorage マニフェストのみ。
新:
- 保存→再起動→読込で同じ Project を再現できることを正規要件とする。
- localStorage 単独に依存しない正規永続化を持つ。
- backend 保存 API と UI を正しく結線する（二重実装を解消）。
- 解析結果・3D も Project から再生成可能にする（生成データの正本管理）。

--------------------------------------------------------------------------------
5. Project Schema
--------------------------------------------------------------------------------
- 単一の Project Schema を正本とし、バージョン管理・マイグレーションを備える。
- 各設計セクションの契約をスキーマで固定する。
- 座標系・単位はスキーマ上の共通フィールドで一元定義。

--------------------------------------------------------------------------------
6. 判定基準（Save / Load の受け入れ）
--------------------------------------------------------------------------------
- 保存した Project を再起動後に同一内容で読込めること。
- 未保存の編集があることをユーザーが認識できること。
- クラッシュ時に復旧経路が存在すること。
- 各設計機能のデータが Project に統合保存され、個別保存に頼らないこと。
