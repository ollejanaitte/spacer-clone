1. R1-05 目的
--------------------------------------------------------------------------------
R1-04で永続化された1業務=1Projectフォルダーを、1業務=1.spacerprojファイルとして
他PCへ安全に持ち運べるよう、書き出し・検査・読込・登録できるようにする。
「正常データを読める」だけでなく「壊れたPackageを既存Projectへ混入させない」ことを最重要要件とする。

2. Package仕様
--------------------------------------------------------------------------------
- 方式: 単一JSONコンテナ（依存追加なし・node:crypto sha256）
- 拡張子: .spacerproj
- 将来の大容量module（road/terrain/bridge/FEM/CIM/assets等）へは
  containerFormatフィールドでZIP等への拡張可能性を確保（R1-05では対象外）

--------------------------------------------------------------------------------
3. .spacerproj構造
--------------------------------------------------------------------------------
{
  "manifest": {
    "packageFormatVersion": "1",
    "containerFormat": "spacerproj-json-v1",
    "projectId": "<uuid>",
    "projectSchemaVersion": "1.0.0",
    "createdAt": "<ISO8601>",
    "files": [{ "path": "project.json", "size": <bytes>, "checksum": "<sha256>" }]
  },
  "files": [{ "path": "project.json", "content": "<Project Data Core JSON>" }]
}

--------------------------------------------------------------------------------
4. Package format version
--------------------------------------------------------------------------------
- PACKAGE_FORMAT_VERSION = "1"
- containerFormat = "spacerproj-json-v1"
- 単一箇所（projectPackage.ts）で管理

--------------------------------------------------------------------------------
5. manifest構造 / checksum方式
--------------------------------------------------------------------------------
- manifest: packageFormatVersion / containerFormat / projectId /
  projectSchemaVersion / createdAt / files[path,size,checksum]
- checksum: SHA-256（node:crypto computeSha256Hex）
- Package生成時にmanifest作成・checksum計算・self-check可能
- Import時にfile list / size / checksumを照合

--------------------------------------------------------------------------------
6. Exportフロー
--------------------------------------------------------------------------------
Project選択 → [業務データ書き出し] → 保存先選択（OS標準ダイアログ） →
Package生成 → self-check → temp→rename安全書込 → 完了通知
- 書き出し成功/失敗/キャンセルをUI表示
- 途中失敗で壊れた最終成果物を残さない（temp→rename）
- 既存Project正本を変更しない

--------------------------------------------------------------------------------
7. Importフロー
--------------------------------------------------------------------------------
[業務データ読込] → .spacerproj選択 → 事前検査（Integrity Check）→
検査結果画面 → 正常なら[読込] → 競合チェック → 安全登録 →
業務一覧追加 → Projectトップを開く（旧メイン画面へ遷移しない）

--------------------------------------------------------------------------------
8. Integrity Check項目
--------------------------------------------------------------------------------
- ファイル破損 / Project Schema / 必須データ / checksum / 容量 / unsafe path
- NGが1つでもあれば読込不可（例外許可なし）
- 総合判定: 読込可能 / 読込不可

--------------------------------------------------------------------------------
9. 競合処理 / 上書きbackup / transactional safety
--------------------------------------------------------------------------------
- 同一Project ID検出 → 上書き / 別Projectとして複製 / キャンセル の3択
- 上書き: 既存を自動backup（.backup/*.spacerbak）→ backup成功確認 → 置換
  （backup失敗時は上書き拒否・既存非破壊）
- 複製: 新Project ID生成・内容維持・R1-02 validator通過
- キャンセル: 何も変更しない
- Import失敗時: 半端Projectを業務一覧に残さない・temp残置なし

--------------------------------------------------------------------------------
10. path traversal等の安全対策
--------------------------------------------------------------------------------
- packagePathSafety: 相対pathの ../・絶対パス・ドライブ文字・NULL等を拒否
- unsafe pathがPackage内に存在する場合、読込前検査で拒否
