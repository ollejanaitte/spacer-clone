2. Phase 3-Fix 内容（Step A）
--------------------------------------------------------------------------------
A. 3D Viewer大型化
   - SceneViewer共通ホスト新設（renderer/camera/OrbitControls/ResizeObserver/
     fit-to-bounds/disposeを共通化）
   - Terrain Moduleページを wide化（max-width 1320px）
   - Viewer高さ clamp(480px, 62vh, 780px) のresponsive対応（固定pixel依存を回避）
   - camera aspect / renderer size は ResizeObserver でコンテナ追従

B. 座標変換不具合（root cause）
   - 原因: TerrainViewerが applyDomainToThreeTransform を built.mesh と
     built.wireframe の両方へ適用（両者は同一geometryを共有）。
     共有geometryに対し domain→three 変換が2回実行され、
     1回目 (x,y,z)->(x,z,-y)、2回目 ->(x,-y,-z) となり
     three.y=-domain.y・three.z=-elevation に化けて Terrainが鉛直に立った。
   - また統合シーン（buildIntegratedThreeScene）は terrain に変換を適用しておらず
     同様に鉛直姿勢だった。
   - 修正: 変換をgeometryに対し1回だけ適用。統合シーンでもterrainに1回適用。

C. 共通Render Coordinate Adapter（一本化）
   - frontend/src/next/modules/renderCoordinate.ts を唯一の正本として新設
   - domainToThree: three.x=domain.x / three.y=domain.z(標高) / three.z=-domain.y
   - threeToDomain / domainVerticesToThree（Local Origin対応・入力非破壊）
   - terrainCoordinate.ts / threeCoords.ts を本Adapterへ委譲し、
     Terrain / Road / Existing / 統合scene / camera / 既存liner・bridgeProject が同一変換を使用

D. 表示修正・統合シーン
   - IntegratedSceneViewer新設 + Terrain Moduleページに
     「統合シーン（Terrain+Road+Existing）を3D表示」トグルを追加
   - 既存Viewer（existingViewerBuilder）もLocal Origin対応・共通変換へ

--------------------------------------------------------------------------------
3. 座標変換 最終仕様
--------------------------------------------------------------------------------
- domain XYZ: X=道路軸方向 / Y=横断方向 / Z=標高（metric）
- three.x = domain.x / three.y = domain.z（標高,Y-up）/ three.z = -domain.y（右側+保持）
- Project Origin（global→project）と Local Origin（project→local描画）を分離
- 変換は表示責任。Terrain / Road / Existing の正本（CIM）を書き換えない
- 既存の R3-00_coordinate_origin_freeze.md 契約を踏襲

8. Phase 4-01 Bridge Layout Contract（Step C）
--------------------------------------------------------------------------------
- BridgeLayoutDocument（schema 0.1.0）を唯一の正本として定義
  bridgeId / name / schemaVersion / metadata / roadReference / bridgeRange
  (startStation/endStation) / abutments(A1・A2) / piers(P1..Pn) / spans /
  skew / terrainReference / existingConditionsReference / validation
- runtime validator（fail-closed）: bridgeId必須・roadReference必須・
  startStation<endStation・A1/A2識別・pier ID重複禁止・station順序・
  span length>0・参照切れ検出・NaN/Infinity reject・schemaVersion検証
- parser: JSON round-trip可能
- 参照境界: Road / Terrain / Existing を ID/reference で接続（正本複製禁止）。
  resolveBridgeLayoutReferences で参照切れ（dangling）を検出
- handoff境界: 下部工（supportId/station/skew）・上部工（spans/skew）へ配置情報を渡す
- 実装:
  frontend/src/next/modules/bridgeLayout/{bridgeLayoutTypes,bridgeLayoutValidation,bridgeLayoutReferences}.ts
