--------------------------------------------------------------------------------
1. 実施目的
--------------------------------------------------------------------------------
「Projectを保存すること」ではなく、
「新統合システムにおいて、何をProjectの唯一の正本として扱うのか」を
型・schema・runtime validation・serialization境界として最小限確定する。
将来すべての設計機能が接続する Project Data Core の正本構造を定める。

--------------------------------------------------------------------------------
2. 実装した責任範囲
--------------------------------------------------------------------------------
- Project schema / type（唯一のProject正本構造）
- current schema version の単一管理
- default Project 生成（createEmptyProject）
- Project ID 生成（crypto.randomUUID）
- runtime validator / parser（zod strictObject）
- serialize / deserialize
- invalid schema rejection
- future migration 用の責任境界（registry + migrateProject）
- modules 8領域の最小placeholder境界
- 上記を保証する unit tests

Project 構造:
  projectId / name / createdAt / updatedAt / schemaVersion / metadata / modules
  modules: road / terrain / bridgeLayout / substructure / superstructure /
           analysis / cim / deliverables（各モジュールは空コンテナ）

5. Project schemaVersion
--------------------------------------------------------------------------------
- PROJECT_SCHEMA_VERSION = "1.0.0"（schema.ts の単一箇所で管理）
- getCurrentProjectSchemaVersion() で参照
- deserialize時にschemaVersion必須・semver形式検証

--------------------------------------------------------------------------------
6. runtime validation方針
--------------------------------------------------------------------------------
- zod strictObject（既存依存 zod 4.4.3 を再利用、新規依存追加なし）
- projectId: uuid / name: min(1) / createdAt・updatedAt: ISO 8601 UTC
- schemaVersion: semver / metadata・modules: record
- unknown top-level field reject・必須field欠落reject・非オブジェクトreject
- TypeScript型のみでvalidation済みとしない（runtimeで必ず検証）

--------------------------------------------------------------------------------
7. serialize / deserialize方針
--------------------------------------------------------------------------------
- serializeProject: parseProject通過後 JSON.stringify（不正Projectはthrow）
- deserializeProject: JSON.parse → parseProject（不正JSON/不正Projectはreject）
- serialize → deserialize round-trip equality をテストで保証

--------------------------------------------------------------------------------
8. migration責任境界
--------------------------------------------------------------------------------
- ProjectMigration interface（from / to / migrate）を定義
- PROJECT_MIGRATIONS registry（現状空）
- migrateProject(input, fromSchemaVersion) が registry を順次適用 → parseProject
- 将来の旧schemaVersion → current変換の責任置き場をコード上で明確化
- 過剰なmigration frameworkは作らない
