4. 多重管理・同期破綻リスク（具体箇所）
--------------------------------------------------------------------------------
R1【最重要】LINER 編集後の project.nodes/members の陳腐化
  - LINER draft → project.nodes は「マッピング確認の commit」時のみ再生成。
  - 以後 LINER を編集しても project.nodes/members は自動再同期されない
    (commitLinerDraft: App.tsx:285-311 は project.nodes を触らない)。
  - FEM 解析・メイン Viewer3D は古い座標のまま → 乖離。

R2 下部工ルートの毎 render 再計算 + 編集損失
  - App.tsx:1363-1409 で CBDM チェーンを毎 render 実行、結果は非永続化。
  - SubstructurePlanningHost は initialSupports を useMemo で再導出 → 再入時に
    ユーザー編集（skew 除く）が失われる可能性。

R3 project.supports（FEM 支点）と下部工 Support[]（配置）が別物
  - 下部工は substructure-project.json に別ファイル保存。
  - 「下部工配置を変えたのに解析モデルの支点が変わらない」が起こり得る。

R4 Apollo draft と project.nodes/members の二重コピー
  - withApolloPhase1Unit2Draft (unit2Draft.ts:412) は draft 内のみ更新。
  - Apollo 表示は draft 優先、解析は project.nodes → 表示と解析で座標が異なり得る。
  - draft.metadata が project.project.id/name を上書きする箇所あり (unit2Draft.ts:420-427)。

R5 解析結果の多重保持
  - result / if3Result / rightResult / project.analysisResults.timeHistory の4系統。
  - commitProject は timeHistory をクリアしない → モデル変更後も古い結果が残る。

R6 座標系の5箇所重複
  - coordinateTransform.ts (display swap) / alignmentAdapter.ts:49 /
    substructure/model.ts:6 / apollo builder.ts:27 / cbdmDocument.ts:394
    （x-east-y-north-z-up ← LINER と異なる規約）

R7 BridgeProject/CBDM/manifest が非永続化
  - 毎 render 再計算。保存・ロードされない。checksum の正しさはその render 内のみ。

R8 上部工 manifest の入力が apolloPhase1Unit2 ではなく geometry snapshot 由来

R9 LINER 生成モデルの材料・断面が fixture（placeholder 値）

R10 resetModelContents が LINER メタデータまで全消し (modelReset.ts)

R11 BridgeWizard handleBridgeGenerated がプロジェクト全体を置換（LINER/Apollo/下部工消失）

R12 多重保存・別ファイルの島
  - 下部工(substructure-project.json) / BridgeWizard(*.bridge.json, /api/bridge) /
    level0 / BusinessProject(localStorage) が相互参照なしで独立保存。
