2. 実際の保存先（何が・どこへ・どの形式で・どのコードで）
--------------------------------------------------------------------------------
【メインFEMプロジェクト (/pro)】
- 保存先: ファイル（ブラウザでは download、Electron ではネイティブ保存ダイアログ）
- 形式: JSON (project.schema.json 準拠のプロジェクトドキュメント)
- コード: App.tsx:737 saveProject() → desktop/projectFileDialog.ts saveProjectFile()
- 保存される内容: project 全体（nodes/members/supports/loadCases/liner/apolloPhase1Unit2/…）
  を serializeProjectForPersistence / serializeApolloPhase1Unit2ForPersistence で直列化。
- 注意: backend /api/projects/save は UI から呼ばれない。
  frontend api/client.ts:247 saveProject() は定義済みだが App の saveProject は
  saveProjectFile (download/native) を使う。つまりバックエンド保存 API は
  フロントエンドの正規保存経路ではない。
- backend/data/projects/autosave.json: 133KB の空スケルトンが残存（gitignore 対象）。
  UI からは書かれない（autosave 凍結）。

【BusinessProject (Design Platform)】
- 保存先: localStorage
  - spacer.designPlatform.businessList.v1 （業務一覧）
  - spacer.designPlatform.projects.<businessId> （マニフェスト）
- 形式: JSON。manifest (schemaId=spacer.contracts.engineering-project v0.2.0)
- コード: businessProjectPersistence.ts save() / saveManifest()
- 内容: ToC のみ（roadRefs/bridgeProjectRefs/analysisRefs/deliverableRefs 等は空配列）。
  子エンティティ本体は無し。contentChecksum は "0".repeat(64) の偽値。
- 実測: サンプル業務作成 → 保存 → localStorage に manifest + businessList が書かれる。
  プロセス再起動（同一ブラウザプロファイル）後も業務一覧・ワークスペースが復元される。

【LINER】
- 線形データはプロジェクト状態に埋め込まれ（project.liner）、メイン保存 (project.json) に
  含まれる。専用の LINER プロジェクト保存は localStorage（importer 経路）。
- importer: localStorage (importerStorage / recoveryManager)

【Apollo】
- ワークスペース状態は localStorage (APOLLO_WORKSPACE_STORAGE_KEY、workspace.ts:120/168)。
- 橋梁モデル入力は project.apolloPhase1Unit2 としてプロジェクト状態に埋め込まれ、
  「保存」はメインの project.json 保存へ委譲。

【IF3 解析結果】
- フレーム文書と同じディレクトリの results/<uuid>.if3.json にサイドカー保存
  （backend if3_persistence.py）。/api/analysis/run で自動実行される経路あり。

【ビューア設定 / UIモード】
- localStorage（displaySize / coordinateTransform / uiModeDefault）

--------------------------------------------------------------------------------
4. Restart 実測
--------------------------------------------------------------------------------
【FEM モデル】
1. cantilever_tip_load を読み込み
2. 保存（project.json ダウンロード）
3. ブラウザプロセスを完全終了
4. 同一プロファイルで再起動 → /pro を開く
5. 結果: 「モデル未作成」（空モデル）。Cantilever Tip Load は復元されない。
   → localStorage にも FEM モデルは書かれていない
     (localStorage = spacer-clone:viewer:displaySize:v1 のみ)。
6. 手動でダウンロード済み project.json を「開く」で読み込めば復元可能。

【BusinessProject】
1. サンプル業務作成 → 保存
2. プロセス終了 → 再起動（同一プロファイル）
3. 結果: 業務一覧・ワークスペースが復元される（localStorage 由来）。

【判定】
- メイン FEM: 保存(ダウンロード) → 再起動 → 手動 Load で復元可。
  自動復元なし。ダウンロードファイルを紛失するとデータ損失。
- BusinessProject: localStorage により再起動で復元可（同一プロファイル時）。
- ブラウザプロファイルが変わる/消えると BusinessProject も消失。

--------------------------------------------------------------------------------
5. 再起動後に消えるもの
--------------------------------------------------------------------------------
- メイン FEM の編集内容（手動 Load しない限り）
- 解析結果（result/if3Result はメモリのみ。プロジェクト保存に含まれない）
- active tab / viewer 状態（カメラ等）
- 入力チェック結果
- サンプル由来の編集（読み込み直しが必要）
- （同一プロファイルなら残る）BusinessProject 一覧・マニフェスト、ビューア設定、
  Apollo ワークスペース、importer プロジェクト

7. 判定
--------------------------------------------------------------------------------
PROJECT_SAVE_VERDICT:
  PARTIAL（保存は機能するが、ファイルダウンロード/ネイティブ保存のみで、
  保存先・バージョン管理・復元導線がない。backend 保存 API は UI 未使用。
  Save As なし。autosave 凍結）

PROJECT_LOAD_VERDICT:
  COMPLETE（手動 Open で JSON を読み込め、値が正しく復元される。FEM モデル実測済み）

RESTART_RESTORE_VERDICT:
  FAIL（メイン FEM モデルは再起動で自動復元されない。ユーザーが手動 Open する必要がある。
  BusinessProject のみ localStorage で復元されるが、子データなし）

DATA_LOSS_RISK:
  HIGH（メイン FEM はダウンロードファイルに依存。ダウンロード紛失・別PC移行でデータ消失。
  autosave 凍結のためクラッシュ時の復旧手段なし。BusinessProject は localStorage 依存で、
  プロファイル消去やブラウザデータ削除で消失。バックエンド保存 API は未使用。）

SOURCE_OF_TRUTH_CONFIDENCE:
  LOW（正本が「Reactメモリ」「ダウンロードファイル」「localStorage」「backend/data」
  に分散し、UI から見える正本が定まっていない。STEP 1-07 で詳細追跡）

--------------------------------------------------------------------------------
8. 重大リスク（即 Discord 通知対象）
--------------------------------------------------------------------------------
- S0候補: メイン FEM モデルは保存しても再起動で自動復元されない。autosave は凍結。
  クラッシュ・誤操作で作業が失われる可能性が高い。
- S1候補: メイン FEM の「正本」がファイルダウンロードのみで、backend 保存 API
  (/api/projects/save) が UI から使われていない（無駄な二重実装 + 正本不明）。
- BusinessProject は「マニフェストのみ + checksum 偽値」。実業務データはどこにも
  永続化されない。
