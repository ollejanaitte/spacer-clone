# 2D平面GUI線形入力エディタ技術構想

## 1. 目標

現行の数値テーブル入力に加え、**2D キャンバス上で線形・橋梁骨格を直接編集**できるようにする。データは引き続き RoadDesignDocument（SSOT）であり、エディタは表示+編集のビューとする。

## 2. アーキテクチャ

### 2.1 レンダリング

- **2D キャンバス**: 既存の preview/DrawingDocument レンダラ（SVG・DXF モデル）を再利用するのが安全。Canvas2D/SVG の選択肢:
  - 案A: **SVG（既存 FormalDrawingSvg を拡張）** —— 現行の描画基盤と同一モデル（DrawingPrimitive）で生成でき、テスト・DXF と同型
  - 案B: Canvas2D —— 高描画性能（多数要素）だが、既存基盤と別系統になる
  - 推奨: **案A（SVG）を基本、必要ならハイブリッド**。編集性（クリック判定・アニメーション）も SVG で十分

### 2.2 データ流れ（編集 → 再計算 → 再描画）

```text
[RoadDesignDocument]
        │ edit (要素を変更)
        v
[AlignmentBundleDraft] ----> [パイプライン evaluate] 
        │                          │
        v                          v
[診断]                      [中間結果(座標/測点/断面)]
        │                          │
        +----→ 2Dキャンバスへレンダリング（図形・ラベル）
```

- **編集は draft を書き換え → パイプライン再実行 → 描画更新**のループ（sourceRevision が変われば stale を検知）。
- キャンバスは「読み取り専用プレビュー（drawing model）」と「編集可能なセレクション（要素ハンドル）」を二層で持つ。

### 2.3 編集操作（コマンド）

| 操作 | 内容 | 実装 |
|---|---|---|
| 選択 | クリックで要素選択（端点/中心/曲線） | ヒットテスト |
| ドラッグ | 移動・伸縮 | ハンドル（端点・中心） |
| スナップ | 端点/交点/クロソイド接点/グリッド | スナップエンジン |
| 寸法入力 | パラメータ（R/A/L/方位角）を数値で編集 | インスペクタ |
| 新規要素 | 直線/円/クロソイドをクリック連打で追加 | ツールバー |
| オフセット | 平行線/拡幅（1次/4次）を距離指定で生成 | ツールバー |
| ピア配置 | 平面上にピアを配置（距離/2点/平行/角度） | ツールバー |
| セクション/主桁 | 平面上に S/G を配置 | ツールバー |

### 2.4 編集を実現する座標系・精度

- 表示座標は **DXF と同じ world (m, XY)**。ビューポート変換（パン/ズーム）のみ行う。
- 編集は「論理値（m・rad）」に丸める（内部 double 精度を維持）。
- スナップ判定の許容差: 画面上でピクセル→ワールド換算（デフォルト 6px ≒ ズーム依存）。

## 3. モジュール分割（既存コードとの関係）

| 新規/既存 | モジュール | 責務 |
|---|---|---|
| 既存 | `liner/drawing/model/*` | DrawingPrimitive 生成（レンダリング用） |
| 既存 | `liner/core/geometry/*` | 要素の評価・座標計算 |
| 既存 | `liner/core/pipeline/*` | パイプライン（再計算・診断） |
| 既存 | `liner/dxf/**` | DXF エクスポート |
| 新規 | `liner/editor2d/*` | キャンバス・ヒットテスト・スナップ・ハンドル |
| 新規 | `liner/editor2d/tools/*` | ツール（移動/伸縮/追加/オフセット/ピア配置） |
| 新規 | `liner/editor2d/commands/*` | 編集コマンド（undo/redo 対応） |

## 4. キャンバス状態

```typescript
type Editor2dState = {
  viewport: { centerX: number; centerY: number; scale: number };
  selection: string[];          // 選択要素ID
  activeTool: ToolKind;
  snapOptions: SnapOption;      // 端点/交点/クロソイド接点/グリッド
  grid: GridSettings | null;
  dragging: DraggingState | null;
  hoveredId: string | null;
};
```

## 5. 既存基盤との整合

- **正本は RoadDesignDocument**。エディタ2Dの描画は DrawingDocument の再生成（永続化しない現行方針）。
- **診断**はパイプラインの診断オブジェクトを再利用（既存 `diagnostics.ts`）。
- **DXF プレビュー**は既存の `mapDrawingDocumentToDxf` と同一モデルでプレビュー可能（正本を維持）。
- **コマンド（undo/redo）** は既存の command stack パターン（Phase2 で design）を踏襲。

## 6. 技術リスク

| リスク | 対応 |
|---|---|
| クロソイドのドラッグ編集（解析式反転が複雑） | 数値最適化（近接点への最小二乗当てはめ）またはパラメータ数値入力にフォールバック |
| 大量要素（ライン100/要素100/ピア500）の描画性能 | SVG ではビュー変換を最小化、要素は必要時のみレンダリング（LOD） |
| スナップ精度（クロソイド接点） | 評価を同一計算関数に統一し、許容差を明確化 |
| 図面（GDRAW）と編集キャンバスのモデル違い | 図面は DrawingPrimitive（出力用）、編集キャンバスは要素ハンドル（編集用）と分離し、変換層で接続 |
| 複数案・リビジョン | 差分表示は DrawingDocument 同士の diff（Phase9 で設計） |

## 7. 受け入れ条件（MVP）

- [ ] 直線/円/クロソイドをクリック連打で追加できる
- [ ] 既存要素をドラッグで移動でき、スナップが効く
- [ ] パラメータ（R/A/L）をインスペクタで編集できる
- [ ] オフセット（平行/拡幅1次/4次）を生成できる
- [ ] ピア・セクション・主桁を平面上に配置できる
- [ ] 編集後、パイプライン再計算・診断が反映される
- [ ] DXF エクスポートが編集後も正しい（DXF parity テスト）
- [ ] undo/redo が動作する
