# 実務ユーザーワークフロー分析

根拠: JIP-LINER 標準手順（Phase1）、現行UI（Phase2）、実設計計算例（SRC-005: 鋼鈑桁橋_設計計算例.pdf）の数値表。

## 1. 実務のジョブ（job-to-be-done）

道路橋上部工設計の標準ジョブは次の6つ。

1. **基準線形の確定**（センターライン・測点・縦断横断）——道路計画（平面・縦断）から橋梁の範囲を切り出す
2. **橋梁骨格の配置**（ピア・径間・斜角・支承）——支持条件を定める
3. **床版・主桁の格点割**（セクション×主桁の交点・支間長・格間長・張出し長・横断間隔長）
4. **主桁高さ・ハンチの決定**（腹板高・ハンチ天端・縦断縦断）
5. **舗装厚・横断勾配の処理**（舗装厚算定）
6. **図面・帳票・解析入力の引き渡し**（平面図・座標表・断面表・3D/解析モデル）

実設計計算例（SRC-005）の「基本寸法一覧」はまさにジョブ3/4の出力である:

- **主桁支間長**（AG1/AG2 主桁ごと・径間別）: 例 `1: 40291.5 / 40020.1 mm`
- **主桁格間長**（格間×主桁）: 例 `1: 5344.0 / 5020.1 mm`（曲線/変断面で非等間隔）
- **横断間隔長**（歩車道境界～AG1～AG2 の横断表）: 例 `1253.4 + 4512.2 + 1253.4 = 7019.0 mm`
- **主桁腹板高**（横断×主桁）: 例 `1: 2580.0 / 2580.0 mm`
- **床版張出し長（法線方向・左右）**

→ これらは **LDIST の出力群＋主桁高さ** に相当し、現行システムの LDIST レポートは実務の要求を直接満たす。

## 4. UX 上の課題（Phase5/6 で解決すべき）

1. **入力が数値テーブル中心** → 2D 図面上で直編集（ドラッグ/スナップ/寸法入力）への移行
2. **確認図が後発** → 入力中に常時ライブプレビュー（エラーをインライン表示）
3. **主桁G×セクションS の可視化が不十分** → 平面図で主桁/セクションを表示し格点を明示
4. **ハンチ/舗装厚の意味が分かりにくい** → 縦断図・断面図で厚みをビジュアル化
5. **帳票が「プログラム別」** → 設計計算書全体のワークフロー（段取り）を案内するUI
6. **エラーがバッチでしか出ない** → 逐次バリデーション（パイプライン診断）を常時実行
7. **実測/実績データの取り込み**（PDF/LINER既存データ）→ Importer を標準化
8. **複数案比較**（橋脚位置変更・線形変更）→ 差分表示・リビジョン管理

## 5. 実務の数値検証基準（Phase3 の GAP_VERIFICATION を受けて）

- 現行ゴールデンは解析参照。**実設計例（SRC-005）の支間長/格間長/横断間隔長/張出し長をゴールデンに取り込む**ことで、実務要求との突合を可能にする（例: AG1 支間長 `40291.5mm` と `evaluateAlignment`/LDIST の出力を1mm以内で一致させる）。
- JIP-LINER 実出力（SRC-004）の座標表・断面表も同様に取り込む。

## 6. 優先ペルソナとナビゲーション

- 現行のタブ構成 `line/station/height/vertical/crossSection/utilities/review` は JIP-LINER のデータ順と一致。**この一覧性を保ったまま、各タブ内を2Dプレビュー統合**する。
- 「線形→測点→高さ→ピア→スパン→出力」の段取りを**プログレスガイド**として表示し、次の未入力ステップを案内。
