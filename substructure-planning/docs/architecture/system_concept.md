# システム構成案（System Concept）

区分: PROPOSED（今回提案）

## 1. 全体方針

「下部工計画・3Dモデリングツール」は、既存の上部工ツール（spacer-clone）から
完全に分離した独立ツールとして構成する。

- 上部工とはコードで密結合せず、JSON交換データのみで連携する（疎結合）。
- 旧Apolloの「サブシステムをデータリンクで接続」の思想を、現代的な
  交換スキーマ + 独立アプリとして再構成する。

## 2. 構成要素

```text
+-----------------------------------------------------------+
|                   下部工計画・3Dモデリングツール            |
|  (LAB_ROOT / prototype)                                    |
|                                                           |
|  [UI]  入力フォーム + 3Dプレビュー (ブラウザ)              |
|  [Core] 入力検証 / 概算数量 / 3D生成 / JSON入出力          |
|  [Data] プロジェクトJSON (独自データモデル)                |
+-----------------------------------------------------------+
        | JSON交換スキーマ（下流）                     |
        v
+-----------------------------------------------------------+
|  上部工ツール（spacer-clone）＝既存、読み取り専用参考        |
|  BridgeDefinition / 支援・支承情報 / 反力(将来)             |
+-----------------------------------------------------------+
```

## 3. 技術構成（最小構成）

- Vanilla TypeScript + Three.js（検証目的に対して最小）
- Vite でビルド・起動（LAB_ROOT 内にのみ依存導入）
- フレームワークはReact等を使わず、DOM + TS のシンプル構成を優先
- パッケージ管理: npm（LAB_ROOT/prototype 内のみ）

方針: 「Reactを使用する場合も過剰なフレームワーク構築は避ける。
Vanilla TypeScript + Three.jsで十分ならそれを優先」

## 4. モジュール分割（案）

| モジュール | 責務 |
|---|---|
| model/ | データモデル・型定義・安定ID |
| validation/ | 入力検証（負値/0/形式/不明単位・座標系） |
| geometry/ | 3Dジオメトリ生成（橋脚・梁・フーチング・杭・支承・橋台・上部簡易外形） |
| quantity/ | 概算体積・杭延長 |
| io/ | JSON保存/読込み、エクスポート（glTF/GLB/STL） |
| ui/ | フォーム・3Dビュー・状態表示 |

## 5. 起動方式

LAB_ROOT/prototype で npm install 後、npm run dev（Vite）。ブラウザで表示。

## 6. 上部工との境界

- 上部工から受け取る: 支点情報（supportId, station, 座標, 支承位置, 桁下高, 反力(任意)）
- 下部工から返す: 下部工の3D形状・寸法・数量・安定ID
- 交換は JSON のみ。実行時は相互にリンクしない。

## 7. 相互運用の原則

- 交換スキーマは上位バージョン耐性（schemaVersion確認、未知項目は無視or明示）
- 単位系・座標系は必須項目
- 未対応形式は fail-closed
